# 누락제로 — 초기 세팅(온보딩) 작업지시서

> 대상: Claude Code가 바로 구현할 수 있도록 화면 · 데이터 · 상태 · 저장 · 완료조건을 분리해 작성한다.
> 전제: **이미 완성된 "이번달 점검표 위젯"과 "대시보드" 컴포넌트의 내부 로직은 수정하지 않는다.**
> 온보딩은 별도 모듈로 추가하고, 위젯에 도달하기까지의 "진입 글루"만 최소한으로 손댄다.

---

## 0. 목표

> "교사가 자신의 업무를 **선택**하면, 표준 업무 데이터에서 점검 항목이 **자동 생성**되고, 필요한 것만 나중에 수정한다."

초기 세팅은 **업무를 만드는 화면이 아니라 업무를 고르는 화면**이어야 한다.
산출물은 다음 4가지가 채워진 상태로, 기존 위젯/대시보드가 그대로 읽어 동작하는 것이다.

```
사용자 프로필  +  선택한 업무(categories)  +  월별 점검 항목(user_tasks)  +  onboarded=true
```

---

## 1. 범위

### 1차에 구현
1. 첫 실행 감지(`settings.onboarded`)
2. 온보딩 5화면: 시작 → 기본정보 → 업무선택 → 생성확인 → 완료
3. 표준 업무 데이터(`workTemplates.ts`) — **개인정보보호만 실제 점검표 완성**, 나머지 업무는 목록·별칭만 두고 "준비 중"(선택 불가)
4. 별칭 검색
5. 선택 업무 기반 월별 점검 항목 자동 생성 → 기존 위젯/대시보드에 연결
6. 재실행 시 온보딩 건너뛰기
7. 초기화 수단(테스트/재설정용)

### 1차에서 제외 (2차로)
- 온보딩 단계 내 세부 항목 수정(→ 이미 완성된 대시보드의 추가/수정/월변경으로 대체)
- 개인정보보호 외 업무의 실제 점검표(공식 감사 매뉴얼 데이터 확보 후 추가)
- 증빙자료 첨부, 감사 대비 출력, 학교급별 항목 필터링

## 2. 데이터 구조

### 2-1. 표준 업무 템플릿 — 신규 파일 `src/renderer/src/data/workTemplates.ts`

```ts
export interface WorkItemTemplate {
  title: string
  description: string
  defaultMonth: number | null      // 월별이면 1~12, 수시면 null
  periodType: 'monthly' | 'always'
  priority: 'high' | 'medium' | 'low'
  evidence: string                 // 기존 UserTask.evidenceMemo(문자열)에 그대로 매핑
}

export interface WorkTemplate {
  id: string                       // 'privacy_protection'  ← 생성될 Category.id 로도 사용
  title: string                    // '개인정보 보호'
  category: string                 // '과학·직업교육 및 정보보호'
  auditCode?: string               // '6-3' (선택)
  aliases: string[]                // 검색 별칭
  schoolLevels: string[]           // ['유','초','중','고','특']  (1차에선 표시용, 필터 미적용)
  available: boolean               // true=점검표 완성, false=준비 중(선택 불가)
  items: WorkItemTemplate[]
}

export const WORK_TEMPLATES: WorkTemplate[] = [ /* 아래 표 참고 */ ]
```

**개인정보 보호 (available: true)** — 현재 `data/templates.ts`의 10개 항목을 그대로 옮긴다.

| title | month | period | priority | evidence |
|---|---|---|---|---|
| 개인정보 보호 계획 수립 | 3 | monthly | high | 개인정보 보호 계획 문서 |
| 개인정보 처리방침 현행화 | 3 | monthly | high | 학교 홈페이지 개인정보 처리방침 |
| 개인정보 취급자 지정 및 현행화 | 3 | monthly | medium | 개인정보 취급자 지정 내부결재 |
| 개인정보 취급자 교육 실시 | 4 | monthly | medium | 교육 결과 등록부 또는 내부결재 |
| 개인정보 파일 현황 점검 | 5 | monthly | medium | 개인정보 파일 현황표 |
| 개인정보 처리 위탁 점검 | 6 | monthly | medium | 위탁 계약서 및 점검표 |
| 개인정보 안전성 확보조치 점검 | 9 | monthly | high | 안전성 확보조치 점검표 |
| 개인정보 보호 자체 점검 실시 | 11 | monthly | high | 자체 점검 결과 보고서 |
| 홈페이지 게시자료 개인정보 점검 | null | always | medium | 점검 결과 메모 |
| 개인정보 유출 사고 대응 점검 | null | always | high | 사고 대응 매뉴얼 |

별칭 예: `["개인정보","개인정보보호","정보보호","정보보안","교육정보","정보업무"]`

**준비 중 업무 (available: false, items: [])** — 목록·별칭만 작성:
정보보안, 과학교육, 현장체험학습, 학교폭력, 학생생활교육, 출결 관리, 학교생활기록부, 방과후학교, 학교도서관 등.

> 기존 `data/templates.ts`는 `workTemplates.ts`로 대체한다(또는 templates.ts가 workTemplates에서 개인정보 항목을 re-export). 위젯/대시보드는 templates를 직접 참조하지 않으므로 영향 없음.

### 2-2. 사용자 프로필 / 진입 플래그 — `settings`에 추가

```ts
// types/index.ts 에 추가
export interface UserProfile {
  userName: string
  schoolLevel: '유치원' | '초등학교' | '중학교' | '고등학교' | '특수학교'
  schoolYear: number       // 2026
  startMonth: number       // 3 (학기 시작 월)
  schoolName?: string
  hasKindergarten?: boolean
}
```

저장 형태(기존 `settings` 객체에 키만 추가, store.ts의 settings 얕은 병합으로 그대로 저장됨):

```jsonc
settings: {
  onboarded: true,
  profile: { userName, schoolLevel, schoolYear, startMonth, schoolName?, hasKindergarten? },
  selectedCategory: 'privacy_protection',
  // 기존 키 그대로: windowBounds, alwaysOnTop, startOnBoot, opacity ...
}
```

### 2-3. 생성 결과(기존 테이블 재사용)
- `categories[]` ← 선택한 각 WorkTemplate → `{ id: work.id, name: work.title, description: work.category, createdAt, updatedAt }`
- `user_tasks[]` ← 각 work.items → `{ id: genId(), templateId: null, categoryId: work.id, title, description, month: item.defaultMonth, day: null, periodType, priority, status:'pending', evidenceMemo: item.evidence, note:'', completedAt:null, pinnedToWidget:false, createdAt, updatedAt, sortOrder }`

## 3. 화면 명세

온보딩은 **위젯 창** 안에서 렌더한다(별도 창 아님). 진입 시 창을 키우고(권장 460×640), 완료 시 위젯 크기로 복귀.
모든 화면은 기존 디자인 톤(크림 배경, 둥근 카드, 코랄 포인트) 유지.

### 화면 1 — 시작 (`StepStart`)
```
누락제로
학교 업무, 놓치지 않도록 도와드립니다.
[ 시작하기 ]
```
- [시작하기] → 화면 2.

### 화면 2 — 기본 정보 (`StepBasicInfo`)
| 필드 | 타입 | 필수 | 기본값 |
|---|---|---|---|
| 이름 | text | 선택 | '' |
| 학교급 | select(유/초/중/고/특) | **필수** | 초등학교 |
| 기준연도 | number | **필수** | 올해 학년도(예: 2026) |
| 학기 시작 월 | select(1~12) | 선택 | 3 |
| 학교명 | text | 선택 | '' |
| 병설유치원 | toggle | 선택 | false |
- 검증: 학교급·기준연도 입력 시에만 [다음] 활성.
- 버튼: [이전] [다음].

### 화면 3 — 업무 선택 (`StepWorkSelect`)
```
맡은 업무를 선택하세요
[ 검색: 개인정보 / 정보 / 과학 ... ]

□ 개인정보 보호
▦ 정보보안        (준비 중 · 선택 불가)
▦ 과학교육        (준비 중 · 선택 불가)
...
```
- 검색: 입력값을 각 WorkTemplate의 `title` + `aliases`에 대소문자 무시 부분일치로 필터.
- `available:false` 업무는 "준비 중" 배지 + **체크박스 비활성**.
- 다중 선택 허용(UI), 단 1차에선 실질 선택 가능 항목은 개인정보 보호.
- 검증: 1개 이상 선택해야 [다음] 활성.
- 버튼: [이전] [다음].

### 화면 4 — 생성 확인 (`StepConfirm`)
```
개인정보 보호 업무에서 다음 점검표가 생성됩니다.

3월
- 개인정보 보호 계획 수립
- 개인정보 처리방침 현행화
- 개인정보 취급자 지정 및 현행화
4월
- 개인정보 취급자 교육 실시
...
수시
- 홈페이지 게시자료 개인정보 점검
- 개인정보 유출 사고 대응 점검

[ 기본값으로 시작 ]   [ 대시보드에서 수정 ]
```
- 선택한 모든 업무의 항목을 월별 그룹 + 수시로 미리보기.
- [기본값으로 시작] → `completeOnboarding()` 실행 후 **위젯**으로.
- [대시보드에서 수정] → `completeOnboarding()` 실행 후 위젯으로 가서 **대시보드 창을 함께 open**(`window.api.openDashboard()`).
- 버튼: [이전] 포함.

### 화면 5 — 완료 (`StepDone`)
```
설정이 완료되었습니다.
2026년 6월 점검표를 시작합니다.
[ 위젯 열기 ]
```
- [위젯 열기] → 온보딩 종료(창 크기 위젯으로 복귀) → 위젯 렌더.
- (구현 단순화를 위해 화면4의 버튼이 바로 위젯으로 보내고 화면5를 생략해도 무방. 둘 중 택1.)

## 4. 상태 관리

### 4-1. 온보딩 폼 상태
- `OnboardingFlow.tsx` 내부 로컬 상태로 관리(별도 전역 store 불필요):
  - `step: number`
  - `profile: UserProfile`
  - `selectedWorkIds: string[]`
  - `query: string`(검색)

### 4-2. taskStore 확장 (`src/renderer/src/stores/taskStore.ts`)
- 상태 추가: `onboarded: boolean`
- `init()` 변경:
  - DB 로드 후 categories/tasks/selectedCategory/loaded 세팅(기존과 동일)
  - **자동 시드 제거** — "비어 있으면 개인정보 시드"하던 로직 삭제
  - `onboarded = settings.onboarded ?? (tasks.length > 0)` 로 계산해 상태에 저장 (마이그레이션: 기존 데이터 보유자는 온보딩 생략)
- 액션 추가: `completeOnboarding(profile: UserProfile, workIds: string[])`
  ```
  selected = WORK_TEMPLATES.filter(w => workIds.includes(w.id) && w.available)
  categories = selected.map(work → Category)
  tasks = selected.flatMap(work → work.items.map(item → UserTask))
  selectedCategory = selected[0]?.id ?? ''
  set({ categories, tasks, selectedCategory, onboarded: true, loaded: true })
  window.api.saveDb({ categories, user_tasks: tasks,
                      settings: { onboarded: true, profile, selectedCategory } })
  ```
- 액션 추가(테스트/재설정): `resetOnboarding()`
  - `set({ categories: [], tasks: [], onboarded: false })`
  - `saveDb({ categories: [], user_tasks: [], settings: { onboarded: false } })`

### 4-3. App 라우팅 (`src/renderer/src/App.tsx`)
- 위젯 창에서: `loaded` 후 `onboarded`가 false면 `<OnboardingFlow/>`, true면 `<MonthlyChecklistWidget/>`.
- 대시보드 창(`isDashboardWindow`)은 기존 그대로(온보딩 영향 없음).

```tsx
if (!loaded) return <Boot/>
if (isDashboardWindow) return <DashboardWindow/>
return onboarded ? <MonthlyChecklistWidget/> : <OnboardingFlow/>
```

## 5. 저장 방식 / 창 제어 (메인·프리로드 글루)

### 5-1. 영속화
- `store.ts`는 수정 불필요(이미 settings 얕은 병합 + categories/user_tasks 저장 지원).
- 프로필/onboarded는 `saveDb({ settings: {...} })`로 저장.

### 5-2. 온보딩 동안 창 크기
- `main/index.ts`에 IPC 추가: `window:setOnboarding(active: boolean)`
  - active=true: 위젯 창을 온보딩 크기(예: 460×640)로, 위치는 유지(필요 시 화면 안으로 보정).
  - active=false: `WIDGET_SIZE`(380×520) 또는 저장된 `windowBounds`로 복귀.
- `preload/index.ts`에 `setOnboarding: (v:boolean)=>invoke('window:setOnboarding', v)` 노출.
- `OnboardingFlow` 마운트 시 `setOnboarding(true)`, 완료(위젯 진입) 직전 `setOnboarding(false)`.

> 위 3개(App.tsx 라우팅, taskStore 시드/액션, main+preload 창 IPC)만 손댄다. **위젯·대시보드 컴포넌트 파일은 불변.**

### 5-3. 재설정 진입(테스트)
- 1차: `resetOnboarding()`을 노출하는 임시 수단 — 택1
  - (a) ⚙️ 설정 메뉴에 "초기설정 다시하기" 한 줄 추가(※ SettingsMenu는 위젯 영역이라 최소 한 줄만 추가, 원치 않으면 생략)
  - (b) AppData의 `nuranzero-data.json` 삭제 후 재실행

## 7. 완료 조건

1. 최초 실행(데이터 없음) 시 위젯 대신 **시작 화면**이 뜬다.
2. 기본정보(학교급·기준연도) 입력 → [다음] 진행된다.
3. 업무선택에서 **개인정보 보호 선택 가능**, 준비 중 업무는 비활성으로 표시된다.
4. 별칭("정보", "정보보호" 등)으로 검색하면 개인정보 보호가 나온다.
5. 생성 확인 화면에서 월별 점검표 미리보기가 보인다.
6. [기본값으로 시작] 시 categories/user_tasks가 생성되고 **위젯에 이번 달 항목이 표시**된다.
7. 앱을 껐다 켜도 온보딩을 다시 묻지 않고 위젯으로 바로 간다.
8. 기존 위젯/대시보드 기능(지연 표시, 완료 체크, 월 드래그, 투명도/크기 조절, 대시보드 슬라이드)이 **그대로 동작**한다.
9. 재설정 수단으로 온보딩을 다시 테스트할 수 있다.
