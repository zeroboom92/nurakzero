# 표준 업무 템플릿 품질 작업지시서

> 대상: 감사 매뉴얼 → 누락제로 세부 점검표 템플릿(`*.v1.json`)을 만드는 작업(Codex/스킬).
> **골든 샘플**: `src/renderer/src/data/templates/privacy_protection.v1.json` — 모든 템플릿은 이 수준을 따른다.
> **자동 검문소**: 작업 후 반드시 `npm run validate:templates` 실행 → **ERROR 0** 이어야 통과.

---

## 0. 핵심 원칙: "쪼개지 말고 큐레이션하라"

매뉴얼 원문을 **줄 단위로 그대로 task로 만들면 안 된다.** (그렇게 하면 출결관리 78개처럼 폭발해서 위젯에서 못 쓴다.)
담당 교사가 **한 달에 실제로 처리하는 단위**로 묶어 **업무당 5~12개**의 점검 항목으로 정제한다.

- ❌ 나쁜 예: 원문 표의 모든 세부 bullet을 1:1 task로 → 78개
- ✅ 좋은 예: 의미 단위로 묶어 10개 (privacy_protection)

---

## 1. 절대 금지 (= 검증기 ERROR)

| 금지 | 설명 | 골든 샘플은 |
|---|---|---|
| **보일러플레이트 description** | `"○○ 영역의 세부 점검내용을 확인하고 관련 증빙서류를 정리한다"` 식 자동 문장 | task마다 **실제로 무엇을 점검하는지** 한 문장 |
| **description 반복** | 여러 task가 사실상 같은 설명 | 전부 다른 실제 내용 |
| **shortTitle 글자수 절단** | title 앞부분을 그대로 잘라 `"출결 처리 관련 규정 준수 여"` | 의미 있는 축약 `"내부관리계획 수립"` |
| **evidence 복붙** | 업무 내 모든 task에 동일한 증빙 목록 | **task별 맞춤 증빙** 2~4개 |
| **task 15개 초과** | 원문 통째 복붙 신호 | 10개 |
| title 없음 / month 비정상(1~12·null 아님) / priority 비표준 / evidence 없음 | 형식 오류 | — |

## 2. task 필드 작성 가이드

각 task는 골든 샘플처럼 작성한다. (필수=앱 동작에 필요, 권장=품질·감사대비 강화)

```jsonc
{
  "templateTaskId": "privacy_001",          // 필수. {templateId 약어}_NNN 형식, 고유
  "sourceAuditItemId": "privacy_internal_management_plan", // 권장. 원본 점검항목 묶음 id
  "title": "개인정보 내부관리계획 수립",      // 필수. 동사형 한 줄, 40자 이내, 원문 조각 금지
  "shortTitle": "내부관리계획 수립",          // 권장. 의미 있는 축약(글자수 절단 금지)
  "description": "개인정보보호 관련 내부관리계획을 수립하고 필수사항, 결재, 제·개정 이력을 확인한다.", // 필수. 실제 점검 내용 1문장
  "taskType": "계획",                        // 권장. 계획/점검/교육/공개/정비 등
  "cycle": "연 1회",                          // 권장. 반복 주기 텍스트
  "recommendedMonth": 3,                     // 필수. 1~12 또는 null(수시). 근거 있게 분산
  "recommendedDay": 31,                      // 권장
  "priority": "high",                        // 필수. high/medium/low (감사 위험도 기준)
  "riskLevel": "상",                          // 권장. 상/중/하
  "isCore": true, "isAuditFocus": true,      // 권장
  "defaultStatus": "todo",                   // 권장
  "checkQuestions": [                         // 권장. 실제 점검 질문 2~5개
    "개인정보 내부관리계획을 수립했는가?",
    "필수사항이 포함되어 있는가?"
  ],
  "evidence": [                              // 필수. task별 맞춤 증빙 2~4개(콤마로 합치지 말 것)
    "개인정보 내부관리 계획", "내부결재 공문"
  ],
  "completionCriteria": "…하면 완료 처리한다.", // 권장
  "sourceBasis": "원본 표 260: …",            // 권장. 매뉴얼 근거(표 번호 + 내용)
  "monthReason": "학기 초에 기준 문서를 먼저 세워야 하므로 3월 권장" // 권장
}
```

### 제목(title) 규칙
- **동사형 한 줄**, **40자 이내**. 예: `개인정보 처리방침 수립 및 홈페이지 공개`
- 원문 문장(`"… 여부 - 출석인정결석·지각·조퇴·결과 사유 및 …"`)을 그대로 넣지 않는다.
- 부모 요약 + 자식 원문을 **둘 다 넣지 않는다**(중복). 하나로 정제.

### 월 배정 규칙
- 전부 3월(기본값)으로 두지 않는다. 업무 성격에 맞춰 **연중 분산**하고 `monthReason`에 근거를 적는다.
- 상시 업무는 `recommendedMonth: null`(수시).

### 증빙(evidence) 규칙
- **task마다 그 항목에 실제로 필요한 증빙**만 2~4개.
- `"A계획,B점검표"`처럼 한 칸에 콤마로 합치지 말고 **배열 원소로 분리**.

## 3. 템플릿(파일) 상위 구조

`templateId`는 인덱스(`index.json`)의 항목과 **정확히 일치**해야 하고, 파일명은 `<templateId>.v1.json`.
상위 필드는 골든 샘플과 동일하게: `templateId, version, schemaVersion, title, displayTitle, description, audit, schoolLevels, aliases, source, sourceAuditItems?, legalReferences, tasks`.

`index.json`의 각 항목: `templateStatus`는 세부 점검표가 **품질 기준을 통과한 경우에만 `ready`**. 아직 정제 안 됐으면 `indexOnly`로 두어 온보딩에서 선택되지 않게 한다.

## 4. 작업 절차 (Codex/스킬)

```
1) 원본 점검항목을 의미 단위로 묶어 업무당 5~12개로 큐레이션
2) 각 task를 §2 가이드대로 작성(보일러플레이트·복붙·원문조각 금지)
3) templateId/파일명/인덱스 정합성 확인
4) npm run validate:templates   ← ERROR 0 확인 (필수)
5) 통과한 업무만 index.json에서 templateStatus: "ready"
```

검증기는 형식뿐 아니라 **보일러플레이트·복붙·절단·폭발**을 잡는다. **ERROR가 남아 있으면 적용 불가.**

---

## 5. 합격 기준

- `npm run validate:templates` → **ERROR 0**
- 샘플 3~5개를 골든 샘플과 눈으로 비교했을 때, 제목·설명·증빙이 **실제 업무 점검표로 바로 쓸 수 있는 수준**
- 업무당 task 수가 5~12개 범위(특수한 경우만 15개까지)
